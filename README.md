# pmxer

pmxer は PMX 形式の編集、検証、保存、プレビューを行うクロスプラットフォームのデスクトップアプリケーションです。

## 方針

- PMX の参照を安定ハンドルで扱い、UI から生の添字を変更しない
- 保存前に検証し、一時ファイルへの保存と再読み込み比較を通過した場合だけ原子置換する
- 構造編集はトランザクションとして一度に確定する
- 編集履歴、診断、参照調査、意味差分を同じ編集層から提供する
- Linux、Windows、macOS のネイティブビルドを同じソースから作る

## 対応範囲

- PMX 2.0 / 2.1 の読み込み、検証、保存後の意味比較、原子置換
- 頂点、BDEF1/2/4、SDEF、QDEF、材質、テクスチャ、ボーン、付与、IK、モーフ、表示枠の編集
- 剛体、ジョイント、SoftBody の保存・編集と対応範囲の診断
- SDEF 変換、ウェイト正規化、準標準ボーンのレシピ、物理チェーン生成、モデル追加結合
- Undo / Redo、参照調査、検証診断、基準との差分、回復保存
- MMD形式のモーション・ポーズ読み込みと、IK・物理を含むプレビュー
- SDL3のネイティブファイルダイアログ、複数文書タブ、回転・ズーム可能な3Dビューポート
- 材質色、面、ボーン、剛体、ジョイント、SDEFマーカーを同じビューポートで確認
- PNG等の一般画像と、非圧縮RGB(A)・BC1・BC2・BC3・BC4・BC5・BC7のDDSテクスチャ
- 安定ハンドルとトランザクションを使用した構造編集
- Transform View による一時的な頂点変形・ボーンポーズ編集とモーフ作成
- Morph Mixer、左右分割、変化量の反転・倍率変更、材質マスク、Bake & Reverse

保存は既定で保持モードを使い、元ファイルを直接上書きしません。一時ファイルへ書き出し、再読み込みした内容の意味比較が成功した場合だけ原子置換します。

## 必要環境

- CMake 3.25 以上
- Ninja
- C++20 対応コンパイラ
- SDL3 開発ファイル（GUI ビルド時）
- ネットワーク接続（GUI と物理プレビューの初回ビルドで依存ライブラリを取得する場合）

## ビルド

```sh
git clone <repository-url> pmxer
cd pmxer
make
make test
```

Makefile は CMake preset を呼び出す薄い操作 UI です。初回の `make` では
`external/libmmd` サブモジュールも自動初期化されます。CMakeを直接操作する場合は、
`CMakePresets.json` の `linux-dev`、`linux-cli`、`linux-clang`、
`linux-release` などを利用できます。

```sh
make cli
make sanitize
make run ARGS="model.pmx"
make run ARGS="info model.pmx"
make PRESET=linux-cli test
make release JOBS=16
```

利用できる操作は `make help` で確認できます。

CLI は GUI なしでもビルドできます。

```sh
make cli
make PRESET=linux-cli run ARGS="info model.pmx"
```

GUI を起動する場合は `make run ARGS="model.pmx"`、ビルドの並列数を指定する場合は
`make JOBS=8` のように実行します。CMake preset を直接操作することもできます。

## Transform View

GUI の `Transform View` は、ビューポートと同じドックレイアウトで使える変形ワークスペースです。
`頂点` タブを開くとリグワークスペースと頂点選択へ自動で切り替わります。ビューポートまたは
Transform View 内の `選択`、`移動 G`、`回転 R`、`拡縮 S` を使って編集し、
`頂点モーフを作成` でPMXへ反映します。

`ボーン` タブもリグワークスペースへ自動で切り替わり、ボーン表示とボーン選択を有効にします。
一度に操作できるボーンは1本ですが、複数のボーンを順番に変形して1つのボーンモーフにできます。
IK、付与、物理などに制御されるボーンは操作できない理由を画面に表示します。

頂点とボーンの編集は独立した一時変形として保持され、タブとビューポートに変更数が表示されます。
一時変形はモーフを作成するまでPMX本体に含まれません。各タブの破棄ボタンはその種類だけを破棄し、
すべてを破棄する操作では確認画面を表示します。頂点の一時変形中は、元の基準位置を薄い点と線で確認できます。

`モーフ` タブではモーフミキサーからグループモーフの作成や頂点モーフへのベイクができます。
拡縮、反転、結合、減算、左右分割、材質マスクは `高度なモーフ操作` 内にまとめられています。
各PMX変更はUndo 1回で戻せます。

## 自然言語による範囲編集

[Codex CLI](https://developers.openai.com/codex/cli)をインストールすると、上部の `AI編集`（Ctrl+J）からChatGPTアカウントを
接続できます。既存のCodexのChatGPTログインを再利用し、未ログインの場合は
`ChatGPTで続行` からブラウザーでログインします。認証情報の保存・更新はCodexが管理し、
pmxerはトークンを保存しません。Codexを検出できない場合は `PMXER_CODEX` に
実行ファイルのパスを指定してください。APIキーによるログインはこの機能では使用しません。
認証と通信には公式の[Codex app-server](https://developers.openai.com/codex/app-server)を使用します。

1. モデルを開き、AI編集パネルの `ビューポートで範囲を選択` を押します。
2. 矩形または投げ縄で編集したい部分を大まかに囲みます。顔・髪・他の衣装が混ざっていても、
   指示と材質・位置・ボーン情報から対象を絞ります。Shiftで追加、Ctrlで切り替え、Escで範囲選択を終了します。
   `対象の材質全体を補完する` は初期状態で有効です。AIが特定した衣装・髪などの材質全体を対象にでき、
   囲みきれなかった端や裏側も含めます。選択範囲内だけを変える場合はオフにしてください。
   `モデル全体から対象を探す` を使えば、範囲選択をせず「髪だけ長く」「服だけ変更」と指示できます。
   `裏側まで選択` を無効にすると、隠れている面を除外します。選択した面は青く表示します。
   通常の頂点・材質選択も利用できます。頂点選択では3頂点とも選択された面が対象です。
3. 「靴だけ黒いローファーに変更」「服を青いワンピースに」「髪だけ1.15倍長く」などを入力し、
   `プレビューを生成` を押します。選択範囲・リビジョンはこの時点で固定します。
4. 対象の材質名・面数とビューポートの編集案を確認し、`編集を適用` で確定します。
   `プレビューを破棄` またはパネルを閉じると元のモデルへ戻ります。
5. 編集全体はUndo 1回で取り消せます。通常の保存・名前を付けて保存でPMXへ書き出します。

対応する編集は単色への変更、移動・回転・拡縮、メッシュの分割による高密度化、平滑化、
法線方向への膨張・収縮、および基本形状の衣装・靴の生成です。
「アップスケール」はメッシュの高密度化として扱い、三角形を1回につき4分割します。
画像テクスチャの解像度や、元にない細部を生成する処理ではありません。
UV・追加UV・ボーンウェイト・頂点／UVモーフを補間し、元の頂点を保持します。
平滑化・膨張では境界を固定して、対象外の面を変形させません。

生成できる基本形状はローファー・ブーツ・半袖シャツ・長袖コート・プリーツスカート・
ワンピース・ズボンです。指示に合わせて寸法・色・密度・形状調整を組み合わせられます。
生成後の高密度化なども含め、編集全体をUndo 1回で戻せます。
既存の髪や服を変形する指示は、既存のテクスチャを保って処理します。長さの変更では毛根・ウエスト側を基準に拡縮できます。
メッシュ処理はバックグラウンドでプレビューを準備し、適用時には検証済みの結果を反映します。
一般的な服装の依頼は近い基本形状への近似として提案し、変更内容と近似の範囲を説明します。
実行できる部分がある場合はその部分を提案し、実行できない部分も説明します。

生成メッシュには対象の近傍頂点からボーンウェイトを転送します。
任意デザインの3D形状・テクスチャ生成、画像テクスチャのアップスケール、身体の補完、
自動衝突回避、衣装の物理設定・専用モーフの自動作成には未対応です。
元モデルが衣装の下の身体を省略している場合、短い衣装へ変えると隙間ができます。
必要に応じて既存の編集機能で調整してください。

Codexへ送るのは指示、選択範囲の大きさ・件数、材質ごとの位置・件数・名前・色・影響ボーンです。
PMXファイル、頂点配列、テクスチャ画像は送信しません。
Codexは読み取り専用の一時スレッドで編集計画を作り、pmxerが型・値域・対象の
安定ハンドル・リビジョンを検証します。複数の処理を独立した作業用モデルで実行し、すべて成功してからまとめて適用します。
部分的な色変更では材質を分離し、変形では共有境界の頂点を分離して選択外の面を保持します。
生成時に置換するのは絞り込んだ対象面だけで、元の頂点や他のPMX要素は保持します。材質の補完を有効にした場合は、取得範囲に接している指定材質の面に限り範囲外も対象にできます。

実通信の生成・保存・再読み込み・Undo/Redoを手元で確認する場合は、テストを有効にしてGUI版を
ビルドした後、次を実行できます。既存のChatGPT認証とプラン利用枠を使用し、出力先へ
3種類のPMXと編集計画を保存します。入力モデルは変更しません。

```sh
./build/linux-dev/pmxer_ai_smoke --live model.pmx build/ai-live
./build/linux-dev/pmxer_ai_smoke --replay model.pmx build/ai-live
# 大まかな全体選択からの靴・ワンピース・ズボン変更、高密度化、髪の変形を検証
./build/linux-dev/pmxer_ai_smoke --broad-live model.pmx build/ai-broad
./build/linux-dev/pmxer_ai_smoke --broad-replay model.pmx build/ai-broad
```

`--live` は一般的なMMDモデルの高さから足元・胴体・スカート付近を選ぶ検証用です。
`--broad-live` は全体を候補範囲として、関係のない面・頂点を保持できることも確認します。

## CLI

```text
pmxer [edit-options] [file.pmx ...]
pmxer <command> [options] ...

pmxer info [--json] model.pmx
pmxer validate [--json] model.pmx [other.pmx ...]
pmxer diff [--json] [--profile logical|preservation] before.pmx after.pmx
pmxer normalize [-o output.pmx] model.pmx
pmxer help [command]
```

GUI起動時は `--font`、`--font-size`、`--resource-dir`、`--renderer`、`--gpu-debug`、
`--no-physics`、`--safe-mode`、`--lang` を指定できます。`PMXER_FONT` と
`PMXER_RESOURCE_DIR` 環境変数も利用できます。

GUIの表示言語は日本語（`ja`）、英語（`en`）、中国語・簡体字（`zh-CN`）、
ロシア語（`ru`）に対応しています。例えば `pmxer --lang ru model.pmx` で
ロシア語で起動できます。`ja-JP`、`en_US.UTF-8`、`zh-Hans` などの言語タグも使えます。
既定の `--lang auto` は `PMXER_LANG`、`LC_ALL`、`LC_MESSAGES`、`LANG`、
OSの優先言語の順に選択し、未対応の言語は英語で表示します。
言語指定はGUIに適用され、PMX内の名前・コメントやCLIのJSONキーは変更しません。
日本語・中国語・キリル文字を含むフォント（Noto Sans CJKなど）を使用してください。
自動検出できない場合は `--font` または `PMXER_FONT` で指定できます。
言語を変えてもドック配置は引き継ぎます。初回起動時は旧形式のレイアウトをバックアップして更新します。

## ログ

診断ログは DEBUG と INFO を標準出力、WARN と ERROR を標準エラーへ出力します。終了コードは、成功 0、検査結果の不合格 1、引数エラー 2、入出力エラー 3、内部エラー 70 です。

## ライセンス

本体のライセンスと依存ライブラリのライセンスは配布物に同梱します。
